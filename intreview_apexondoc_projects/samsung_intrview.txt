❓ Q: Can you describe a time you found a defect that others missed? How did you identify it?


🟢 Situation:
In one of my projects, we were testing an Android version of a  ---->[ Microsoft Teams-like collaboration app]. The app had passed regular functional and UI tests on popular devices like all the devices. It was scheduled for release across a wide range of OEM devices.

🟢 Task:

My responsibility was to conduct device compatibility and real-time performance testing across different Android versions and manufacturers, especially for budget/mid-range devices that are often overlooked but widely used.

🟢 Action:

While running exploratory and background usage tests on a mid-range Android device (with limited RAM), I noticed that the app was getting force-closed automatically after switching between apps and coming back to the chat screen.

I dug deeper using ADB logs and discovered that =======>  [[ Android's memory manager was killing the background service ]]] that maintained socket connections for real-time messaging. This issue was not reproducible on high-end phones where memory was not a concern, which is why it was missed during initial testing.

🟢 Result:

I logged the issue with a detailed analysis including logcat traces, steps to reproduce, and a memory usage report. The dev team optimized background service handling and added fallback logic for socket reconnection.

As a result, we prevented real-time messaging failures on 30% of our target devices and improved app stability ratings in early user feedback. My findings were added as part of mandatory test cases for future device certification.
